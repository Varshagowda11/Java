Java
Java is a programming language.

Language
Language is a medium to communicate between two entities.
Entities: Which exist in the world and occupy space.
Example: Human beings communicate with each other using language.

Programming Language
Programming language is a medium to communicate between humans and machines/system.
Example:
- Human gives instructions to a machine.
- The machine understands the instructions through a programming language.

Types of Programming Languages
1. Machine Level Language (Low-Level Language)
2. Assembly Level Language (Mid-Level Language)
3. High-Level Language

2. Types of Programming Languages
1. Machine Level Language (Low-Level Language)
- It is understandable by machines.
- It is a binary language.
- It has two representatives:
  - 0
  - 1
- It is near to machines and far from humans.

2. Assembly Level Language (Mid-Level Language)
- It is in a human-readable format.
- We have a set of instructions called mnemonics and keywords (predefined words).
- Examples: ADD, MOV, SUB, MUL, etc.
Difficulties:
- Machines cannot understand Assembly Language directly.
- We need to convert Assembly Language (AL) into Machine Level Language (MLL).
- We need software called an Assembler.
- 8086 instructions are an example.
Advantages:
- Easier for humans to write and understand.

3. High-Level Language
- It is in a human-readable format.
- Examples: Java, Python, C, C++ and C#.
- Machine cannot understand High-Level Language directly.
- We need to convert High-Level Language (HLL) into Machine Level Language (MLL).
- We need software:
  - Compiler
  - Interpreter
Advantages:
- Easier to learn.
- Easier to write.
- Easier to debug and maintain.

Two Types of HLL
1. POPL
2. OOPL

POPL – Procedure Oriented Programming Language
- Focuses on procedures/functions.
- Example: C.
- No OOPS.
OOPL – Object Oriented Programming Language
- Focuses on objects.
- Examples: Java, Python, C++.
Java is a High-Level Object-Oriented Programming Language.

3. History of Java
James Gosling is known as the Father of Java.
History
1. James Gosling was working in Sun Microsystems as a software developer.
2. One day, he came up with an idea to develop a programming language which could run on any system.
3. He needed a team and called it the Green Team.
4. He started a project. The project name was Green Project.
5. He finished and published it in the year 1991 as Green Talk.
Naming of Java
1. One day, they stood outside a company with a coffee shop. They thought their programming language idea would grow like a tree.
2. So, they kept the tree name called Oak.
3. Oak was already a company name with a business, so they could not continue using it.
4. Then they changed the name in 1995 to Java.
5. Java is a coffee name. When they were building the project, they drank coffee called Java coffee.
6. Then, in 2010, the Oracle company took over Sun Microsystems.
7. So, Java comes under Oracle (with the Java chair/name under Oracle).
Important timeline:
- 1991 – Green Project / Green Talk
- 1995 – Java
- 2010 – Oracle acquired Sun Microsystems

### 5\. Platform Dependent and Platform Independent

### Platform Dependent

* A program that is dependent on a particular platform is called platform dependent.

* Example: C language.

Example:

* Smith writes a program on a 32-bit Windows system.

* It may not run directly on a 64-bit or another platform.

* We need platform-specific compilation.

### Platform Independent

* A program that is not dependent on a particular platform is called platform independent.

* Example: Java.

Example:

* Smith writes a Java program on a 32-bit Windows system.

* The same program can run on 32-bit Linux, 64-bit Windows and other platforms using the appropriate JVM.

Note:

* C is a platform-dependent language.

* Java is platform independent but dependent on JDK/JRE (as written in the notebook).

* Java is platform independent because of Bytecode.

### 6\. JDK (Java Development Kit)

JDK = Java Development Kit

JDK is software that contains many sub-softwares inside it.

* It contains JRE and Compiler inside it.

* It provides an environment to both write and run programs.

### JDK Structure

```text
JDK (Java Development Kit)
│
├── JRE (Java Runtime Environment)
│   │
│   ├── JVM (Java Virtual Machine)
│   │   │
│   │   ├── JIT (Just-In-Time Compiler)
│   │   │
│   │   └── Interpreter
│   │
│   └── In-built Packages / Classes / Libraries
│
└── Compiler
```

### 7\. JRE (Java Runtime Environment)

* It is a sub-software of JDK.

* It contains JVM and in-built packages inside it.

* It provides an environment to run Java programs.

### 8\. Compiler

* It is a sub-software of JDK.

* It is used to convert from HLL to MLL.

* It will read the code once.

### 9\. JVM (Java Virtual Machine)

* It is a sub-software of JRE.

* It contains JIT and Interpreter inside it.

* It is a machine used to run Java programs.

### 10\. JIT (Just-In-Time Compiler)

* It is a sub-software of JVM.

* It will speed up the interpreter.

### 11\. Interpreter

* It is a sub-software of JVM.

* It is used to convert HLL to MLL.

* It will read the code line by line.

### 12\. Compilation and Execution

Can we send Compiler to Interpreter without a class file?

* Platform independent.

* Secure.

* The compiler works to send the code to JRE and JVM.

* JVM only understands Bytecode, so we need a class file to push to the Interpreter.

### Compilation Process

Flow:

Java Source File (.java)

The place to write the Java program

Compiler

* Takes source file as input

* Checks for syntactical mistakes

* If mistake → CT error

* If no mistake → Generates bytecode

Class File (.class)

Bytecode – Intermediate language (neither understandable by humans nor directly by machines)

Interpreter / JVM

* Takes class file as input

* Checks for logical mistakes

* If mistake → RT error

* If no mistake → Executes the program

Output

### Errors

* CTE – Compile Time Error

* RTE – Runtime Error

### Compilation

* Compilation: The process of converting from Source File to Class File.

* Compile Time: The time taken to convert Source File to Class File.

### Execution

* Execution: The process of converting from Class File to Output.

* Runtime / Execution Time: The time taken to convert Class File to Output.

Note: Your notebook uses simplified descriptions of some Java components. For technical accuracy, the Java compiler (`javac`) converts `.java` source code into `.class` bytecode. The JVM executes that bytecode using its execution engine, which includes an interpreter and JIT compiler.
